For Rust CLIs

Stop compiling Rust CLIs from source

crabx <crate> runs a crates.io CLI from prebuilt releases. Works with any repo that supports cargo-binstall.

$ npx @kixel/crabx install

Puts the native crabx binary on your PATH, so nothing after this needs Node. Or install it with:

# macOS / Linux
$ curl --proto '=https' --tlsv1.2 -fsSL https://crabx.kixel.me/install.sh | sh
# Windows
> powershell -ExecutionPolicy Bypass -c "curl.exe --proto '=https' --tlsv1.2 -fsSL https://crabx.kixel.me/install.ps1 | Out-String | iex"
# Anywhere with a Rust toolchain
$ cargo install crabx

Then run any crate:

$ crabx ripgrep TODO
$ crabx hyperfine 'sleep 0.1'
$ crabx install just  # puts `just` on your PATH

crabx itself is prebuilt for x86_64 and arm64 on Linux (glibc 2.28 or later), macOS, and Windows.

How it works

  1. 01

    Find

    Looks up the crate on crates.io and finds the binary its own repository released, the same way cargo-binstall does.

  2. 02

    Cache

    Keeps it per crate and version. The next run starts instantly, even offline.

  3. 03

    Run

    Runs it with your arguments, and updates it in the background.

crabx never builds binaries itself; a crate's repository opts in by publishing them. No release for your platform? crabx --build <crate> compiles it with Cargo instead.

Motivation

I was tempted to make a new CLI tool in JavaScript just for npx. Fuck that. Write it in Rust, and pre-compile binaries so it launches just as fast.

Security

  • Why maintainers opt in instead of crabx hosting builds: you run the binary the crate's author released, so you trust the same people you already trust with cargo install. A central build service would be one target holding every crate's binaries.
  • When a release has GitHub attestations, crabx verifies them and requires the signer to be the crate's repository or crabx's pipeline running in it. A bad attestation is an error, never a warning.
  • Once crabx has verified an attested release of a crate, it refuses that crate's unattested ones.
  • An unpinned run waits 24 hours before running a new release, since a hijacked release is usually yanked within hours.
  • Third-party builds from cargo-quickinstall need --allow-quickinstall.

For maintainers

If cargo binstall finds your binaries, crabx does too. Publish them with dist or upload-rust-binary-action, alongside release-plz if you use it.

Or run crabx init once: it writes one workflow that builds and attests binaries for six platforms each time you publish to crates.io.

$ crabx init
wrote /home/you/mycrate/.github/workflows/binaries.yml; commit it and push it to main

The repository must be public and be the one your crate's repository field names. Build jobs get read-only tokens; only the publishing job, which never runs your crate's code, attests archives and writes releases. See the pipeline.
